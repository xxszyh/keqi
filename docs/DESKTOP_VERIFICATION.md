## Windows 0.11.1：MOOC 连接与读取修复

日期：2026-10-12。本节补充上述 0.11.0 记录，不表示已发布 GitHub Release。

真实已登录会话中，`home.htm` 的客户端跳转经过 HTTP → HTTPS 升级，初始 `loadURL` 拒绝并报告 `ERR_ABORTED (-3)`；替代课程页实际已经加载。旧版本将取消的初始请求直接上报为“操作未完成，请重试”。修复只接续这种取消，并要求本次导航已提交、地址有效且未被阻止；切换文档时丢弃旧快照，网络错误仍失败。单次导航和脚本读取共用 30 秒上限。

继续验证发现课程接口返回 HTTP 200 / `code:0` 和正常课程数据，但 Electron 的 `session.fetch` 返回空 `Response.url`，JVM 因而误报登录失效。由于课程请求已通过地址及只读入口校验，且 `redirect:'error'` 禁止重定向，现使用已验证的请求地址。此行为与 [Electron 的 fetch 限制说明](https://www.electronjs.org/docs/latest/api/session#sesfetchinput-init)一致。页面执行与导航时序参照 [webContents 文档](https://www.electronjs.org/docs/latest/api/web-contents)。

页面快照另外携带官方页面运行时提供的数字账号；仍需登录 Cookie 验证，与 HTML 中的账号冲突时拒绝连接。明确的登录失效显示重新连接提示。

新增匿名回归通过真实 Electron → JVM → SQLite，覆盖静态账号、客户端跳转、缓慢替代页面、运行时账号、缺少 Cookie、账号冲突、被阻止的客户端/服务器跳转，以及课程、作业和考试完整读取。客户端跳转和空响应网址两个用例均先在旧行为下失败，再验证修复。

实际账号检查只读取官方页面、课程目录与任务数据，写入隔离的临时课期数据库；没有提交作业、进入答题或修改平台数据。调试没有操作手机或手机系统文件。

真实会话端到端检查完成：MOOC 与 SPOC 共读取 9 门课程、571 条平台任务（包括历史记录），连接状态为 `ok`。匿名平台回归、桌面 UI/进程恢复及共享核心检查通过。

Windows 0.11.1 安装 EXE 与便携 ZIP 已构建；最终打包的 `Keqi.exe` 通过 UI/持久化检查。打包仅收录 `build/ui/` 的界面资源，验证器拒绝其他 `build/` 内容，防止临时诊断文件进入成品。安装器的完整安装/卸载未在日常用户目录执行。
