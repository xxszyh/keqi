# 课期电脑与手机联动：功能草案

当前状态（2026-10-11）：0.11.0 开发实现已加入仓库。下文保留原设计目标；以本节和 [实际使用说明](DESKTOP_USAGE.md) 区分已实现与后续目标。

- 已实现 C1—C6 的主要流程：双端独立读取、局域网配对与交换、课程选择、手动待办/备注/子任务/批量操作/重复任务、桌面托盘与本地通知。
- `Workspace` / `TaskService` / `Repeats` 为共享核心；平台纯解析继续复用安卓源文件，MOOC 课程分页提取为 `MoocCatalog`。
- 首版事务存储使用 SQLite 元数据中的版本化 JSON，未拆成下文建议的逻辑 SQL 表。增量以实体修订选出变化的完整字段版本头，操作回执随响应交换；没有压缩历史、分页拉取或长连接推送。
- 电脑生成证书并在二维码中提供 SHA-256 指纹；手机核对该证书、等待电脑确认并保存 Keystore 加密令牌。使用 IPv4 和单台电脑工作区。
- epoch 或工作区不匹配时停止并保留 outbox。自动重建旧主机日志、跨工作区迁移、多主机和 IPv6 尚未实现；首版不会自动将旧工作区整库覆盖到另一台电脑。
- 自动检查覆盖规则、匿名页面、实际 Electron UI、HTTPS 认证/去重/撤销和 SQLite 回滚。iQOO / OriginOS 实机扫码、真实学校账号、锁屏提醒和网络隔离情况尚未验证。

---
原始需求草案（实施前，2026-10-11）：六项核心方向已确认，已形成推荐框架。当前实现情况见上文。

“已确认”表示用户明确选择；“建议”表示待审阅的功能细节，不等于已授权实施。本文件记录需求，不代表现有版本已支持这些功能。

## 1. 产品目标

让同一用户在电脑上集中整理课程任务和个人待办，在手机上随时查看、修改和接收提醒；两端在同一局域网且互相可连接时自动交换更新，并且各自可以独立使用。

电脑主要补充大屏管理、键盘操作、批量编辑和托盘提醒。手机主要承担随身查看、快速记录和离开电脑后的提醒。两端拥有相同的核心任务数据，不要求手机只能查看。

### 用户已经确认

| 编号 | 决定 | 直接影响 |
| --- | --- | --- |
| C1 | 首版改为同一网络下自动同步，无需第三方云服务 | 电脑内置局域网同步入口；离网时各自保存，下次连接后补同步；无需租服务器或购买订阅 |
| C2 | 电脑版重点做手动待办、子任务、备注和批量编辑 | 首版重点是任务管理；资料库与完整学习计划没有被选为重点 |
| C3 | 电脑托盘常驻及到期通知 | 关闭主窗口后仍能提醒；需要明确退出与休眠后的行为 |
| C4 | 两端分别登录官方平台，并独立读取任务 | 手机未运行时，已登录的电脑也能读取更新；反之亦然 |
| C5 | 课程启用、移出、恢复两端一致 | 临时筛选各端独立；长期保留课程的选择共享 |
| C6 | 手动待办覆盖学习与个人事务，可不关联课程，支持重复 | 需要同时扩充电脑与安卓端的任务编辑能力 |

2026-10-11 根据用户最新要求替换 C1；C2—C6 保持不变。异地自动同步留作后续扩展，不属于本首版验收范围。

### 首版系统建议

优先 Windows，与用户当前电脑一致；Android 保持现有手机端。macOS、Linux 尚未承诺，系统版本、安装形式与技术选型留到框架设计确定。

## 2. 当前版本作为基础

以本地 0.10.0 源码为依据：

- 两个平台的官方登录、课程目录、可识别的作业/测验/考试/互评读取。
- 日期分组列表、搜索、平台/课程/类型/状态筛选、截止日历。
- 课程启用、持久移出、撤销和恢复。
- 人工处理标记、补充截止、稍后提醒、免打扰。
- 本机保存任务，区分完整读取、部分读取与旧缓存。

当前安卓版本没有双端同步、用户新建待办、子任务、备注或重复任务。电脑联动不能仅增加一个电脑查看器，还需要安卓功能和数据迁移。

核查依据：[使用说明](USAGE.md)、[当前架构](ARCHITECTURE.md)、[Store](../mobile/src/com/keqi/reminder/Store.java)、[MainActivity](../mobile/src/com/keqi/reminder/MainActivity.java)、[任务身份生成](../mobile/src/com/keqi/reminder/Collectors.java)。现有任务身份包含平台、本机账号 UUID、课程、任务及阶段；经 [LoginActivity](../mobile/src/com/keqi/reminder/LoginActivity.java) 复核，平台用户 ID 另存于 `sourceAccount`，现有任务 ID 不能直接跨设备去重。迁移需保留旧编号与人工修改；不能用课程名或任务名匹配。

## 3. 首版建议功能范围

| 功能组 | 用户看到的行为 | 确定程度 |
| --- | --- | --- |
| 任务总览 | 今日、近期、逾期、全部、日期待确认；作业、测验、考试、互评与手动待办统一检索 | 建议，继承现有任务能力 |
| 平台读取 | 学习通/MOOC 各自登录、刷新、显示读取范围及异常；两端读取同一任务后只保留一项 | 独立读取已确认；展示细节为建议 |
| 课程管理 | 搜索、按平台收起、批量启用、移出、恢复；操作在两端生效 | 共享范围已确认；大屏操作为建议 |
| 手动待办 | 新建、编辑、处理、恢复、删除；课程可选，支持个人事务 | 已确认；字段与回收站为建议 |
| 子任务 | 在手动待办或平台任务下列出步骤，调整顺序、逐项勾选 | 已确认；适用范围与操作细节为建议 |
| 备注 | 任务说明和链接；两端查看与编辑，长文本方便在电脑输入 | 已确认；首版建议纯文本，不做完整文档编辑器 |
| 批量编辑 | 多选后处理/恢复、调整优先级、标签及提醒；手动待办可批量删除 | 已确认；批量动作范围为建议 |
| 重复任务 | 每日、每周、每月；可选星期和结束条件；每次独立状态与提醒 | 重复任务已确认；具体规则为建议 |
| 日历 | 月/周查看截止与重复待办；点击日期查任务和编辑详情 | 建议；尚不等于完整课程表或时间安排工具 |
| 电脑提醒 | 托盘常驻、到期通知、通知点击打开任务；稍后提醒与免打扰 | 托盘及通知已确认；细节为建议 |
| 双端同步 | 同一局域网自动交换任务与修改、离线后补同步、冲突保留、状态可查、手动重试 | 局域网自动同步已确认；异常处理为建议 |
| 设备管理 | 首次扫码配对、查看已配对设备、解绑旧设备、换机后重新配对 | 建议；无需第三方同步账号 |
| 数据备份 | 可导出/恢复任务与用户编辑；导出不包含平台会话或配对密钥 | 建议，用于换机和本机数据恢复 |
| 桌面操作 | 键盘快捷键、可调整窗口宽度、列表与详情并列、深浅外观 | 建议；沿用现有简洁列表方向 |

### 手动待办建议字段

标题、可选课程、截止时间、优先级、标签、备注、子任务、提醒和重复规则。没有截止时间也可以创建；它不会被当成逾期，也不会生成没有依据的截止提醒。

首版建议只区分待处理/已处理；步骤进度由子任务表示，暂不增加多个状态流转或项目看板。

### 子任务与备注的边界

- 平台任务也可以附加“查资料、完成计算、撰写报告、检查提交”等步骤。
- 勾完子任务不自动向平台提交，也不自动宣称平台已完成；可以显式标记课期已处理。
- 平台更新保留用户的步骤和备注。
- 首版备注以文字和链接为主；本机文件路径不被当成手机可访问的附件。

### 批量操作的边界

- 可以批量改变课期的人工处理、优先级、标签及提醒。
- 批量删除手动待办可撤销/从回收站恢复。
- 平台来源信息不作为可随意改写的普通字段；补充截止保留原始时间。
- 平台任务首版建议继续通过处理标记或课程管理控制显示，不增加含义模糊的“删除平台任务”。

## 4. 重复任务规则建议

1. 以设置的日历周期产生实例，而不是从上次完成时刻重新计算。
2. 完成某次只处理本次；整个系列另有暂停/结束动作。
3. 支持修改本次或本次及后续；已经处理的历史实例保留。
4. 逾期实例不会自动变成已完成；暂停系列不抹掉已有记录。
5. 两端离线时遇到同一个周期，恢复同步后只能形成一个实例。
6. 月末不存在对应日期时，建议提供“当月最后一天/跳过当月”的规则选择，并展示下一次日期。
7. 首版建议日/周/月与常规星期选择；农历、法定节假日调休和复杂表达式留到后续。

## 5. 哪些数据共享，哪些各端独立

| 数据 | 建议行为 |
| --- | --- |
| 平台课程及任务、原始状态和截止 | 共享，保留读取来源与核实情况；旧缓存不能覆盖新证据 |
| 课程启用、移出与恢复 | 共享，用户已确认 |
| 手动待办、子任务、备注、优先级、标签、重复规则 | 共享；两端都可以修改 |
| 人工处理标记、补充截止 | 共享；平台读取不能覆盖人工记录 |
| 任务提醒时间与稍后提醒 | 建议共享，避免两端显示不同的处理意图 |
| 是否发送本机通知、通知声音、免打扰时段 | 建议各端独立，方便电脑和手机在不同使用场景下调整 |
| 搜索、筛选、分组收起、窗口尺寸与外观 | 各端独立，不因另一端操作突然改变当前页面 |
| 登录密码、验证码、平台 Cookie、平台会话 | 不进入双端同步；每端通过官方页面登录 |
| 平台读取健康状态 | 保留设备来源；手机登录过期不能被显示成电脑也已过期 |

设备配对建立同步工作区，与学习通/MOOC 登录是两件事。关联设备不代表另一台设备自动获得平台登录会话。

同一同步工作区内，平台账号不同的课程和任务应分开呈现，不自动拼成一个账号。切换、断开某设备的平台登录，不应被误解释为删除另一端及共享区全部数据；解绑、清除本机缓存和删除共享数据需要分别表达。

## 6. 自动同步与冲突：用户行为要求

- 进入软件、保存修改和恢复局域网连接后自动尝试同步；电脑在运行且已配对手机可连接时尽快交换更新。
- 电脑关闭、退出或休眠，手机离开该局域网时停止交换，显示“等待电脑上线”或“等待局域网连接”；不把暂时失联报成任务丢失或平台登录失败。
- 暂时离线仍能查看缓存、修改任务、创建待办和使用已安排的本地提醒；界面显示尚未同步的修改。
- 不承诺安卓被强行停止或系统限制后台时即时接收电脑更新；重新打开/恢复允许后台运行后补同步。
- 显示双端同步的上次成功、待上传数量、冲突和失败原因；平台读取状态单独显示，避免混淆。
- 不同字段的修改尽量同时保留，例如电脑改备注、手机改优先级。
- 同一字段的离线并发修改保留两个版本，允许选择；不静默丢弃长文本、子任务或任务处理记录。
- 课程移出和手动待办删除都要传播其操作意图，避免另一端的旧记录重新带回；显式恢复可撤销排除。
- 同一条同步消息重试或同一平台任务被两端读取，不产生重复任务或重复实例。
- 一个设备退出或丢失，不影响另一设备已经保存的任务；支持解绑和重新关联。

这里只确定预期行为。身份核对、版本排序、冲突合并、加密与保存方案在框架设计中说明。

## 7. 托盘与通知：用户行为要求

- 首次说明主窗口关闭后驻留托盘；托盘有打开软件、查看近期任务、刷新和明确退出。
- 可选择开机启动；系统通知点击打开对应任务，支持本地已处理和稍后提醒。
- 真正退出、电脑关机或休眠时，电脑不会继续读取新任务或发送本机通知；手机继续独立运行。
- 恢复电脑运行后补做读取和同步，集中展示错过的提醒，避免连续弹出大量历史通知。
- 两端默认各自提醒；处理状态同步到另一端后取消其后续提醒。首版不以“电脑在线”为由静默关闭手机提醒。
- 断网时没有收到另一端的新处理状态，可能仍按本机缓存提醒；不把跨设备绝对去重作为首版保证。
- 通知权限关闭、平台需要重新登录和同步服务不可达分别显示，不影响已经保存的数据。

## 8. 典型使用流程与未来验收

| 场景 | 必须出现的结果 |
| --- | --- |
| 手机读到课程作业，电脑和手机在可互通的同一局域网 | 自动同步后电脑出现同一任务，保留课程名、任务类型和时间证据 |
| 电脑再读取同一作业 | 与手机来源合并，不生成两份同一阶段的任务 |
| 电脑创建不关联课程的个人待办，并添加子任务与备注 | 手机自动收到，并可以编辑和逐项处理 |
| 手机离线处理任务，回到可连接电脑的局域网后同步 | 电脑显示新的处理状态并取消后续本机提醒；平台状态仍如实显示 |
| 电脑移出课程，手机暂时离线 | 手机重新同步后一起排除；下次平台读取不把课程恢复 |
| 电脑和手机离线修改同一备注 | 原内容和两份修改均可找回，用户可以处理冲突 |
| 两端到达同一重复任务周期 | 恢复同步后只出现一个该周期实例；完成本次不终止未来周期 |
| 电脑关机或手机在外使用移动网络 | 手机仍能独立读取、编辑及安排本机提醒；修改等待下次局域网连接后交换 |
| 电脑重新开机并驻留托盘，手机重新可连接 | 自动补同步两端积压的修改；不要求手动导出文件 |
| 同一 Wi-Fi 禁止设备互访，或防火墙阻止连接 | 显示网络不可达及对应处理方式；自动发现失败时可更新连接地址，设备隔离需换可互通网络 |
| 配对后电脑 IP 或端口变化 | 重新发现并核对已配对电脑身份；地址变化不产生新工作区或重复任务 |
| 局域网没有互联网 | 已保存数据和手动修改仍可同步；平台读取单独显示暂不可用 |
| 现有安卓用户升级 | 保留已有人工标记、补充截止、移出课程和提醒；首次双端同步不会覆盖原数据 |

这些是未来设计与实现的验收要求，尚未通过实现或实机验证。

## 9. 局域网连接与运行条件

首版由正在运行的电脑版提供局域网同步入口，手机主动连接。没有第三方项目的调用额度、闲置暂停或订阅费用；数据保存在各端本机，容量和备份由本机设备承担。首版建议一个电脑作为该工作区的同步主机，配对个人手机；多电脑接力作为后续扩展。

- “相同网络”指手机能连接电脑的局域网地址，不要求两端都用 Wi-Fi；电脑网线和手机 Wi-Fi 可以属于同一个可互通网络。
- 同一 Wi-Fi 名称不保证设备互访。校园网、访客网络、不同子网或路由器隔离可能阻止连接；输入 IP 只能绕过发现失败，不能绕过隔离。
- 默认先自动发现，首次扫码配对；发现失败时提供地址更新入口。可尝试个人路由器或热点连接，实际互通能力需要实机验证。
- Windows 防火墙只按所选可信局域网与必要应用/端口放行，不要求关闭防火墙。手机局域网权限、后台限制与电脑休眠分别显示。
- 电脑需处于运行或托盘驻留状态才能交换；手机无需依赖电脑读取平台或发送本机提醒。电脑关闭时未同步修改保存到下次连接。
- 手机后台自动交换受安卓调度限制；前台连接后及时补同步，不承诺系统强行停止时即时送达。
- 局域网交换不依赖互联网；各端读取学习通/MOOC 仍需要访问官方平台。

上述为连接设计与验收条件，尚未在用户校园网、热点或手机后台环境完成验证。首次关联、重新配对、冲突保留和数据导出都应有可理解的界面；不要求用户自行部署独立服务器程序。

## 10. 建议后续扩展

以下功能没有被确定为首版重点，仍保留扩展位置：

- 完整课程表、上课提醒、校历与调休规则。
- 文件附件、课程资料库、笔记编辑器。
- 桌面小组件、微信提醒和跨设备通知自动分工。
- 公告/班群消息、学校单独考试系统、更多课程平台。
- 多人共享、团队协作、其他桌面操作系统。
- 不同网络下的同步、多电脑作为同步主机；将来可替换传输 Adapter，仍沿用任务和合并规则。

不自动作答、提交或开始考试，继承现有读取和人工处理边界。

## 11. 功能确定后需要交付的框架设计

框架设计必须覆盖电脑外壳与界面、可复用的平台读取能力、两端任务模型、手动待办/重复实例、局域网发现与配对、数据隔离、冲突和删除恢复、失联后补同步、手机数据升级、独立通知以及发布方式。

已形成 [推荐框架](DESKTOP_ARCHITECTURE.md) 与 [同步协议设计](DESKTOP_SYNC_PROTOCOL.md)，覆盖模块、数据流、目录、迁移及实施顺序。它们属于待审阅设计，不代表已经实现或用户已经授权开发；目前不创建电脑工程、不改安卓行为、不部署同步服务。
