# 0.2.0 连接修复

用户设备：iQOO Neo10 Pro+ / OriginOS 6。根据用户录屏检查旧版的 MOOC 和学习通连接流程。

录屏中的 MOOC 已经显示个人课程（MOOC 5 门、SPOC 4 门），点击课期「完成连接」仍被拒绝。旧代码只认 DOM 中含学期编号的学习链接；当前个人中心使用点击式卡片，课程显示与这些链接并不等价。新版先验证服务器页面中的登录账号，再调用个人课程接口，读取两类课程和全部可识别分页，使用课程、学校及学期编号生成稳定课程身份。部分范围或分页失败时保留已读课程，并提示覆盖不完整。

学习通录屏中输入验证码后仍停留在登录表单，但课期提示已连接。旧代码仅检查 Cookie 非空，登录表单也会生成普通 Cookie。新版核对受保护页面和账号编号，在未登录时拒绝保存连接；每轮同步也重新核对登录状态及已绑定账号。换账号后不会把新账号数据合并进原账号。

旧版给学习通使用电脑浏览器标识，登录表单发生横向溢出。改用手机浏览器标识后，公开官方入口实际进入移动登录页，Edge 手机尺寸检查中页面宽度与视口同为 390px。还加入页面缩放、刷新、平台 JavaScript 对话框与错误提示；平台自己的验证码与密码交换代码继续在官方页面执行。允许官方第一方旧 HTTP 回跳升级为 HTTPS，保留原始签名查询参数；保持证书验证，不开启全局明文连接。

验证码登录后未跳转的具体服务端原因，无法从录屏证实。不能把回跳兼容或页面布局修正当作已验证的短信登录根因；新版是否能在用户实际账号、该机 WebView 中完成登录，仍须用户安装后检查。未使用录屏里的手机号、密码或验证码，也未申请短信。提取的私人视频帧在排查结束后清理，不包含在安装包内。

参考的第一方页面与脚本（2026-10-08 检查）：

- [学习通官方登录入口](https://i.chaoxing.com/)；手机浏览器模式实际进入 `passport2.chaoxing.com/mlogin`。
- [学习通官方登录脚本](https://passport2.chaoxing.com/js/fanya/login.js?v=20260908)：密码和验证码登录成功后使用平台返回的 URL 回跳。
- [MOOC 个人中心](https://www.icourse163.org/home.htm) 与其 [个人课程模块](https://www.icourse163.org/pub/h/home/desktop/modules/course/index_2082ba183029c0b8331837c05d1dbe39.html)、[SPOC 模块](https://www.icourse163.org/pub/h/home/desktop/modules/spocCourse/index_ab79ef1fa840ac9c8f639334982d727c.html)：课程列表 RPC、分页参数及课程卡片字段。
- [MOOC 官方核心脚本](https://mc.stu.126.net/pub/s/core_210ab52d6feda6bfdd39c5f6c8b03fb4.js)：请求包装使用 `edu-script-token` 与 `csrfKey`；新版采集请求补齐这两个字段。匿名实际请求会返回 `code=0` 但课程结果为 null，所以成功响应码不能证明已登录。
- [Android WebView](https://developer.android.com/reference/android/webkit/WebView) 的浏览器和脚本对话框设置。

复跑与结果见「验证记录.md」。新版使用与 0.1.0 相同的个人签名，版本编号为 2，支持覆盖安装。安装后在设置中分别重新登录两个平台；首次同步后核对平台课程数与一项作业的截止和提交状态。
