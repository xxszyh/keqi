# 0.5.0 学习通连接与独立课程选择

用户确认 0.4.0 已能登录学习通，新截图显示真实的「我学的课」和多门课程，但「完成连接」仍提示尚未登录。旧判定要求服务器页面包含学校 `fid` 或特定账号声明；当前课程首页是另一类受保护页面。回归用真实格式的课程链接和有效账号 Cookie、但去除旧声明，旧生产判定出现 AssertionError。另一个回归复现先匹配旧 `UID` 别名、忽略当前 `_uid` 时拒绝有效账号。

新版点「完成连接」后，重新打开官方受保护课程首页，使用刚才完成登录的 WebView 会话，读取新加载的课程 DOM；无需把密码交给原生请求，也不把缓存课程页加上旧 Cookie 当作登录证据。验证继续限定官方 HTTPS 课程入口，检查账号会话、登录表单和可解析的课程/班级记录；有服务器账号时仍核对一致。优先使用 `_uid`，明确的游客值不能由旧别名提升为登录成功。读取中间登录页、缺少会话或账号不一致都会拒绝连接。课程 DOM 临时用于解析，密码输入的值在返回原生前剔除，没有新 JavascriptInterface 或 TLS 绕过。

新 `ChaoxingCourses` 共用于连接与同步，识别 `stucoursemiddle`、`studentcourse` 等课程链接，以及卡片上的隐藏课程/班级字段。字段形态可见 [原适配参考](https://github.com/DanMo661/Xuexitong-mcp/blob/ebce2cc735bc7acc45fac7ccf32bcefe1a6b2a54/xuexitong_mcp/client.py) 和 [旧门户隐藏字段示例](https://github.com/Closty/chaoxing/blob/master/cx.py#L111)。查询参数大小写/顺序变化和重复封面链接不再漏读或制造重复选择。只保留真实课程/班级编号；未读到 CPI 时保留课程选项并报告入口未完成，不编造编号。补齐入口信息时，沿用该课程原来的选择和本机任务身份。

连接成功即保存课程。同步也先发布课程列表，再逐课读取作业，后来失败仍保留选择与旧作业。后台原生请求不能验证会话时，可使用同样受限的浏览器验证；会话须再次匹配已连接账号。课程页已有可用课程时，不再把学校字段缺失作为同步的必经失败点。学习通单页的 HTTP 403 作为权限/读取错误处理，实际未授权或登录页回跳仍要求登录。隐藏的课程跳过后续作业请求，原有显示过滤和提醒投递复核继续生效。

设置的学习通平台卡片新增「选择课程（数量）」：对话框只显示学习通，支持单独全选、全部隐藏与恢复，批量消息只含学习通课程键。MOOC 也有独立入口；作业页的选择入口仍显示两个平台。原生状态刷新后保持当前平台范围。覆盖升级沿用应用包名、签名和数据库版本，保留 MOOC 连接及已有选择。

通过 43 项规则/适配器、99 项连接/课程、7 项浏览器 DOM 联检、19 项基本界面、16 项课程显示和 18 项独立选择检查；旧回归先失败再通过。公开页面回跳联检及 APK 编译、签名、资源校验通过。DOM 联检使用明确的课程样例和测试会话，不代表真实采集。GUI 工具再次因无法确认当前浏览器网址而停止，未取得用户已登录页；只有截图，无法证明其真实 HTML 与某个测试样例完全一致。0.5.0 在 iQOO Neo10 Pro+ / OriginOS 6 的连接和采集仍待手机验证。
