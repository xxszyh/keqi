# 0.4.0 学习通学校回跳修复

用户的两张截图显示，手机和电脑两种登录模式均停留在登录页，原生提示为「未打开跳转：http://i.mooc.hdu.edu.cn」。把该地址送入 0.3.0 的实际 `LoginNavigation.browserTarget`，得到拒绝结果，回归先出现 AssertionError。用户补充电脑 Edge 能正常登录，最终进入 [学习通官方课程首页](https://mooc1-1.chaoxing.com/visit/interaction)。因此这次已证实的是课期拦截了学校登录回跳；此前匿名页面能打开验证码入口的检查没有覆盖这一登录后的跳转。

新版手机和电脑登录入口的 `refer` 均指向该官方 HTTPS 课程首页。对截图中的精确学校主机，个人首页和 `/base` 回跳转为官方课程首页，不传递学校查询参数或票据；其他学校域名、非标准端口和不相关路径没有加入这个映射。原生 HTTP 客户端共用跳转规则，保留每次目标地址自己的 Cookie 域隔离。继续禁止明文网络和验证 TLS 证书；没有把学校地址强行升级成证书不匹配的 HTTPS，也没有开放全部 HTTP。

「完成连接」与后台同步请求同一个受保护课程首页，使用最终响应地址的 Cookie 判断账号。课程页提供服务器账号时须与 Cookie 账号一致；登录表单、普通匿名 Cookie 和错误页继续拒绝。课程页省略学校字段时，匹配的服务器账号仍可验证登录；同步另取学校元数据，并核对同一账号。元数据缺失单独报错，不把已验证登录误报为尚未登录，也不猜学校编号。已验证的学校字段直接交给课程读取，避免再次请求旧首页。

会话备份和重置增加 `mooc1-1.chaoxing.com`。MOOC 个人课程采集和课程选择沿用原有实现，覆盖安装不删除本机记录或已选课程；使用原来的签名和应用包名，版本号为 0.4.0 / 4。

检查结果：79 项连接与课程检查、40 项规则/适配器检查、19 项界面检查和 16 项课程显示检查通过。公开浏览器联检用实际 Java 路由重放学校地址，手机/电脑两种模式都能到达真实官方课程入口，匿名会话随后返回官方登录页；没有填写账号、发送验证码或模拟登录成功。首次及保留 Cookie 再次打开移动页、切换电脑页均正常，无页面脚本错误。

电脑学校 HTTP 请求在本机网络返回 403，对应 HTTPS 请求出现域名证书不匹配，不能据此判断所有网络的学校服务状态。GUI 页面读取工具因无法可靠确定当前浏览器网址而停止，未取得用户已登录页作为解析验证样本。真实 iQOO Neo10 Pro+ / OriginOS 6 上的账号登录、课程采集和后台通知仍待验证。APK 编译、签名和匿名检查不替代手机实测。
